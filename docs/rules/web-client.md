# 웹 클라이언트

dfragon.com 첫 화면에서 설치 없이 쓰는 웹 클라이언트의 계약을 정한다. 결정의 이유와 고르지 않은 대안은 [ADR 0004](../adr/0004-web-client.md)에 있다. 검색과 캡처 회차의 동작은 [캐릭터 검색](character-search.md)을 따른다. 앱 경계와 점수 엔진 위치는 [Architecture Overview](../architecture/overview.md), 웹 entry와 공용 검색 코어의 package는 [ADR 0008](../adr/0008-desktop-discontinued.md)을 따른다.

## 위치와 화면

- 웹 앱은 dfragon.com 메인 첫 화면에 둔다. 각본으로 움직이는 목업 창은 두지 않는다. 첫 화면의 바탕은 어두운 canvas 토큰 하나이고(밝은 바탕은 쓰지 않는다), 웹 앱 상자 하나만 페이지 가운데에 두며, 사이트 상단 바, 푸터, 배경 그림, 소개와 안내 문구는 두지 않는다. Neople 오픈 API BI 가이드에 따라 페이지 아래 가운데에 어두운 바탕용 회색 Neople 로고(86×24)만 `https://developers.neople.co.kr` 링크로 둔다(2026-11-03 저장소 소유자 결정, 2026-11-04 시안). 앱 화면 문구는 합니다체다.
- 상단 바와 파티, 공대 화면을 폭 1080px 상자 안에 합성한 컴포넌트를 `@dfragon/client/web`으로 내보낸다. 상자 높이는 화면 내용에 맞추고 고정하지 않으며, 상자는 페이지 세로 가운데에 둔다. 앱 화면의 문서 전체 드래그 차단, `user-select: none`, `100dvh`는 이 상자 밖의 사이트에 적용하지 않는다.
- 파티와 공대 화면은 카드 격자 대신 표 하나다. 배치와 행 상태는 아래 [화면 구성](#화면-구성)을 따른다.
- main merge는 검색 엔진의 크롤링을 막은 `dev.dfragon.com`에만 자동으로 배포한다. `dfragon.com`은 저장소 소유자가 운영 배포를 수동 실행할 때만 바뀌고, 그 시점은 소유자가 정한다(2026-11-01 저장소 소유자 결정). `dev.dfragon.com`은 Cloudflare Worker가, `dfragon.com`은 GitHub Pages가 맡으며, 절차는 [Web 배포](../../apps/web/README.md#배포)에 있다.

## 화면 구성

파티와 공대 화면은 같은 열의 표로 그린다. 결정의 이유는 [ADR 0012](../adr/0012-party-raid-table-rows.md)에 있다.

- 표는 헤더 32px, 행 48px이다. 열은 자리, 캐릭터(초상화 36px와 이름 칸), 서버, 모험단, 길드, 직업, 명성, 점수, 스냅샷이고 열 폭은 내용과 관계없이 고정한다.
- 파티는 네 행이고 자리 열에 번호만 둔다. 공대는 R, Y, G 파티마다 파티 헤더 행(파티 배지와 "찾은 수/4") 아래 네 행을 두고, 자리 열에 파티 색의 옅은 면과 글자로 된 배지(`R1`~`G4`)를 둔다.
- 이름 칸은 올리면 테두리, 초점을 받으면 신호색 테두리와 링을 그린다. 이름이 빈 행은 늘 테두리를 두고 "캐릭터 이름" placeholder를 보이며, 이름을 읽는 동안에는 두지 않는다.
- 점수 열은 딜러 "장비"와 파란 숫자, 버퍼 "버프"와 초록 숫자다. 근사값은 `≈`와 점 밑줄로 보이고 이유는 마우스 설명과 보조 기술로 전한다. 상위, 랭커는 명성 숫자 색과 이름 옆 배지만 바꾸고 행 바탕은 그대로 둔다.
- 실패와 오류는 모험단 자리부터 세 칸을 합친 한 줄 글자다. 검색 결과 없음(`캐릭터를 찾지 못함`), OCR이 이름을 읽지 못함(`닉네임을 읽지 못했습니다. 직접 입력해 주세요.`), 이름 없는 Enter(`캐릭터 이름을 입력해 주세요.`)는 노란 글자이고 초상화 칸은 비운다. 검색 오류는 빨간 글자다. 캡처 회차의 상세 정보 오류는 모험단, 길드, 직업을 두고 명성과 점수 자리에 빨간 글자를 둔다. 직접 조회(이름 칸 Enter, 서버 선택)는 상세까지 한 요청이라 상세 오류도 검색 오류처럼 보인다.
- 검색 오류와 상세 정보 오류의 문구는 API 오류 응답의 `error.message`를 그대로 쓴다. 응답을 받지 못한 실패와 보내기 전에 거절한 입력만 클라이언트 문구를 쓴다.
- 회차 진행은 세 점과 단계 이름이다. 이름 인식, 캐릭터 검색은 모험단 자리에, 상세 정보 확인은 명성과 점수 자리에 두며 지난 점은 신호색, 지금 점은 깜박인다.
- 찾은 캐릭터의 이름을 고치는 동안 모험단 자리에 "Enter로 조회"를 둔다. 공대의 추정 선택은 이름 옆 "추정" 배지와 모험단 뒤 경고색 안내다.
- 같은 이름 후보가 여럿인 행은 파티, 공대 모두 이름 옆에 "후보 N" 칩을 두고, 누르면 행 아래 팝오버로 후보 창이 열린다. 창에는 초상화 타일만 명성 순으로 두고 타일 아래에 서버와 명성을 둔다. 타일을 한 번 누르면 그 후보로 확정하고 창을 닫으며, 확정하는 동안 모험단부터 직업까지 상세 정보 확인 진행을 둔다. 결정은 [ADR 0013](../adr/0013-candidate-and-server-popovers.md), 식별 흐름은 [캐릭터 검색](character-search.md#웹의-파티-식별-흐름)에 있다.
- 서버 버튼은 아래로 4열 2줄 서버 목록 팝오버를 연다. 고르면 바로 그 서버로 조회한다.
- 스냅샷을 켜면 찾은 행마다 스냅샷 열에 순번 배지 하나를 둔다. 같은 자리면 신호색 외곽선, 자리가 바뀌면 신호색으로 채운 배지, 스냅샷에 없는 모험단이면 빨간 "없음" 배지다. 공대의 순번은 `파티-순번`이다. 스냅샷을 켠 채 찾지 못한 행은 모험단 자리에 점선 테두리의 직접 입력 칸을 둔다.

## 지원 범위

웹 클라이언트는 데스크톱 브라우저만 지원하고, 휴대폰과 좁은 화면은 지원하지 않는다(2026-11-01 저장소 소유자 결정). 모바일 앱(native client)도 만들지 않는다. 휴대폰과 좁은 화면용 레이아웃, 입력을 두지 않으며, 창이 앱 상자보다 좁으면 상자 안에서 가로로 스크롤한다.

## 입력

웹은 세 입력을 지원하고, 세 입력 모두 같은 표의 행에 결과를 채운다.

- **닉네임 검색**: 행의 이름 칸과 서버 선택으로 그 자리만 조회한다.
- **스크린샷 붙여넣기**: 페이지에서 붙여 넣은(Ctrl+V) 이미지 한 장을 `{ width, height, rgba }` 프레임으로 바꿔, 지금 보이는 화면(파티, 공대)의 회차 하나를 시작한다. 파티는 화면 컴포넌트가 프레임 전체를 받아 crop하고, 공대는 공용 공대 crop이 브라우저에서 12행 결과를 만들어 컴포넌트에 넘긴다.
- **화면 공유**: 브라우저의 `getDisplayMedia`로 공유받은 던파 창에서 회차 프레임을 읽는다. 던파 창은 창 모드에서도 제목 표시줄이 없어(`WS_POPUP`) 공유 프레임이 곧 게임 client다. 폭이나 높이가 홀수이면 브라우저가 오른쪽이나 아래 1px을 버리며(1067 → 1066), 이 프레임을 보정하지 않고 그대로 쓴다.

### 화면 공유 연결

- 상단 바의 게임 연결 칩을 누르면 그 클릭 안에서 `getDisplayMedia`로 창 공유를 요청한다. 칩 말고는 공유를 요청하지 않는다. 웹에는 캡처 소스 목록이 없다.
- 공유를 받으면 그 창이 연결된 캡처 소스 하나가 되고, 칩은 연결됨으로 바뀐다. 연결 전 칩은 신호색 주 버튼 "화면 공유"이고, 연결 뒤에는 success 색의 pill 칩 "게임 연결됨"이다. 인식 중, 확인 필요, 캡처 실패 칩은 같은 pill 모양에 각자의 색을 쓴다. 연결된 동안 칩을 다시 누르면 새로 고른 창으로 바꾸고, 공유 창을 닫거나 거절하면 지금 연결을 그대로 둔다.
- 연결된 동안 웹은 마을에서 지금 보이는 화면(파티, 공대)의 구성이 바뀌면 그 화면의 회차를 자동으로 시작한다([마을 자동 인식](#마을-자동-인식)). 켜고 끄는 토글과 설정은 두지 않는다.
- 캡처 버튼은 남긴다. 누르면 공유 화면에서 프레임 한 장을 읽어 지금 보이는 화면의 회차를 시작하고, 같은 구성이어도 바로 다시 인식한다. 연결된 동안에도 붙여 넣은 이미지는 그 붙여넣기로 시작한 회차에서만 읽는다.
- 사용자가 브라우저에서 공유를 멈추면 연결 전 상태로 돌아간다. 파티는 창 선택을 바꾸거나 캡처를 중지할 때처럼 행과 마지막 캡처 시각도 비운다. 공대는 연결이 사라져도 끝난 회차의 행을 남기므로, 공대 화면의 칩과 문구는 붙여 넣은 공대 회차처럼 그 회차의 결과를 보인다.

### 마을 자동 인식

던파 창을 공유한 동안 브라우저 host는 약 1초마다 공유 화면의 지금 프레임 한 장을 읽어 아래 순서로 판정한다. 결정의 이유와 고르지 않은 대안은 [ADR 0005](../adr/0005-web-town-auto-recognition.md)에 있고, 판정 대상 화면은 [ADR 0006](../adr/0006-web-town-watch-current-screen.md), 같은 구성 기준은 [ADR 0007](../adr/0007-web-town-compare-binarized-name-crops.md)이 바꿨다.

- **마을 판정**: 게임 화면 오른쪽 위의 지구본 아이콘이 보일 때만 마을로 본다. 마을이 아니면 자동으로 회차를 시작하지 않고 화면(파티, 공대)과 표도 바꾸지 않는다.
- **지금 화면만**: 웹이 파티 화면이면 게임의 파티 프레임에서 네 자리 이름 crop만, 공대 화면이면 공대 상세 창에서 12행 이름 crop만 본다. 다른 화면의 창은 보지 않는다. 구성이 새로우면 지금 화면의 회차를 시작하고, 그 화면의 창이 없거나 구성이 같으면 표를 그대로 둔다.
- **화면 전환**: 자동 인식은 웹의 화면(파티, 공대)을 바꾸지 않는다. 화면은 사용자가 바꾼다.
- **같은 구성**: 비교 기준은 그 화면(파티, 공대)의 마지막 회차가 읽은 프레임의 이름 crop이며, 그 화면의 회차가 아직 없으면 보이는 구성은 새 구성이다. 자동 회차, 캡처 버튼, 붙여넣기로 시작한 회차가 모두 기준을 바꾼다. 이름 crop의 위치는 기존 검출기가 준다(파티는 `detectPartyFrameGeometry`의 자리별 이름 영역, 공대는 `cropDNFRaidParticipantNicknames`의 행별 이름 crop). 자리 수가 다르거나, 한 자리라도 crop 크기가 다르거나, OCR과 같은 글자 이진화 결과에서 글자 여부가 다른 픽셀이 일정 개수 이상이면 다른 구성이다. 이진화는 그 화면의 OCR 닉네임 전처리를 그대로 쓴다(파티는 BT.601 회색의 Otsu 이진화, 공대는 가장 어두운 채널의 Otsu 이진화와 선택 행 테두리, 떨어진 픽셀 제거). 공대 이름 칸의 배경은 색이 움직이고 반투명하므로 RGB 픽셀을 비교하지 않고, 특정 색을 고정 임계값으로 찾지도 않는다. 글자 하나만 다른 이름은 다른 구성으로 잡는다. 판정에서 OCR로 이름을 읽지 않는다.
- **2번 연속**: 새 구성은 지금 화면에서 2번 연속 같은 crop으로 보일 때만 회차를 시작한다. 게임 화면이 바뀌는 순간의 프레임으로는 회차를 시작하지 않는다. 사이에 웹의 화면이 바뀌거나 그 화면의 창을 찾지 못한 틱이 끼면 처음부터 다시 센다.
- **회차**: 구성이 바뀌면 캡처 버튼과 같은 전체 회차를 시작해 모든 자리를 비우고 다시 채운다. 구성이 같으면 회차가 없으므로 사용자가 직접 고친 자리가 남는다. 자동 회차도 회차로 세어 모험단 스냅샷의 회차 번호가 오른다.
- **진행 중과 실패**: 회차가 진행 중이면 판정하지 않는다. 회차가 실패로 끝나도(글자 인식 실패, 공대 창 미확인) 그 프레임이 기준이 되어 같은 장면을 다시 시도하지 않는다. 다시 시도는 캡처 버튼으로 한다.
- **주기**: 약 1초다. 판정 주기를 ms 단위로 맞추는 timeout과 그 테스트는 두지 않는다.

판정 함수(마을, 지금 화면의 crop 비교, 2번 연속)는 host와 분리한 순수 모듈로 두고 합성 입력으로 테스트한다. 공유 화면 이미지와 crop은 이 판정에서도 브라우저 밖으로 보내지 않는다([전송 정보](#전송-정보)).

웹은 브라우저의 화면 공유 권한을 쓴다.

### 붙여넣기 안내 범위

붙여넣기의 기본 안내는 Alt+PrtSc다. 던파 창은 창 모드에서도 제목 표시줄이 없어 Alt+PrtSc 이미지에는 게임 화면만 들어간다. 창을 고르기 전의 상태 문구와 파티 프레임을 찾지 못했을 때의 문구도 Alt+PrtSc를 안내한다.

파티 프레임 검출은 프레임 좌상단을 게임 client 원점으로 보므로, 던파 창이 왼쪽 위에 있지 않은 전체 화면 스크린샷이나 임의 영역 캡처에서는 파티를 찾지 못한다. 공대 상세 창은 프레임 어디에 있어도 찾지만 수치는 1920×1080 이하 프레임에서만 읽는다.

찍는 방법별로 파티 검출이 되는 조건은 다음과 같다(2026-11-01 Windows 10 실기, 1920×1080 100% 배율, 창 모드 1067×600, [Issue #1085](https://github.com/dungeon-and-dragon/dfragon/issues/1085)). 공대 상세 창은 프레임 안 위치를 가리지 않으므로 아래 조건과 무관하다.

| 방법 | 이미지 | 파티 검출 |
| --- | --- | --- |
| Alt+PrtSc(활성 창) | 게임 client만(1067×600) | 창 위치와 무관하게 된다 |
| PrtSc(전체 화면) | 화면 전체(1920×1080) | 던파 창이 화면 왼쪽 위(0, 0)에 있을 때만 된다. 던파 창이 앞에 있으면 Windows 클립보드에 이미지가 들어오지 않아 다른 창을 앞으로 둔 뒤 눌러야 한다 |
| Win+Shift+S 사각형 | 끈 영역 | 화면 왼쪽 위에 있는 던파 창을 (0, 0)부터 끌어 담을 때만 된다. 시작점이 client 원점에서 벗어나면 되지 않는다 |
| Win+Shift+S 창 | 고른 창의 client(1067×600) | 창 위치와 무관하게 된다 |

안내 문구는 Alt+PrtSc만 적고, 나머지 방법의 조건은 이 절이 정한다.

## 전송 정보

| 정보 | 가는 곳 |
| --- | --- |
| 입력하거나 인식한 닉네임, 고른 서버 | API(`api.dfragon.com`)의 캐릭터 검색 |
| 조회한 캐릭터의 서버와 캐릭터 ID | API의 캐릭터 상세, 초상화 전달 |
| 붙여 넣거나 공유한 화면 이미지와 그 crop | 브라우저 밖으로 보내지 않는다 |
| 공대 행에서 읽은 직업명, 수치와 초상화 비교 거리 | 브라우저 밖으로 보내지 않는다. 인식한 닉네임과 비교로 고른 캐릭터만 위 검색, 상세 요청에 쓴다 |

- OCR은 `onnxruntime-web` worker로 브라우저에서 한다. 모델은 첫 붙여넣기나 첫 화면 공유 때 사이트에서 받으므로 닉네임 검색만 하는 사용자는 받지 않는다. 받는 동안 회차의 상태 문구는 모델을 받고 있다고 알린다. `dev.dfragon.com`(Cloudflare Worker)은 COOP, COEP 헤더로 cross-origin 격리되어 WASM이 최대 8 thread로 돈다. `dfragon.com`(GitHub Pages)은 이 헤더를 붙일 수 없어 WASM이 단일 스레드로 돈다. 두 사이트 모두 WebGPU가 있으면 쓴다.
- API는 운영 사이트 `https://dfragon.com`과 dev 사이트 `https://dev.dfragon.com`의 `GET`, preflight에만 CORS를 허용한다. dev 사이트도 운영 API를 부르며, workers.dev 주소에서도 열리도록 같은 origin의 `/characters*`, `/items*`를 Worker가 운영 API로 넘긴다. 로컬 웹 개발 origin은 [API 안내](../../apps/api/README.md#준비할-입력)의 `WEB_DEV_ORIGINS`로만 더한다.
- 장비 점수와 버프 점수는 API가 상세 응답에 넣은 값만 보인다. 브라우저는 점수 엔진을 받거나 로드하지 않는다([점수 엔진 경계](../architecture/overview.md#점수-엔진-경계)). 점수가 없으면 `-`로 둔다.

## 초상화 전달

웹은 후보 초상화를 네오플 이미지 서버 대신 API에서 받고, 얼굴 크롭과의 비교는 브라우저에서 한다. 네오플 이미지 서버를 직접 쓰지 않는 이유는 [ADR 0004](../adr/0004-web-client.md#확인한-사실)에 있다.

- API는 네오플의 PNG를 변환하지 않고 그대로 전달한다.
- API는 초상화를 서버 메모리에 캐시하거나 저장하지 않는다. 응답의 `Cache-Control`로 브라우저 캐시만 쓴다.
- API 캐시에는 [Issue #870](https://github.com/dungeon-and-dragon/dfragon/issues/870)에서 뺀 캐시 인터페이스와 캐시 바이트 상한을 두지 않는다.
- 경로, 입력 검증, 오류는 [캐릭터 검색](character-search.md)이 정한다.

## 단축키

웹에는 전역 단축키가 없다. 페이지에 포커스가 있을 때 행 자리 맞바꾸기(Alt와 위, 아래 방향키)만 키로 받는다. 캡처, 스냅샷, 복사는 버튼으로만 하며 단축키를 두지 않는다(2026-11-03 결정). 게임 창이 앞에 있으면 페이지가 키를 받지 못하기 때문이다.

Alt와 왼쪽, 오른쪽 방향키는 브라우저의 뒤로, 앞으로 가기와 겹친다. 앱 상자 안에 포커스가 있을 때는 맞바꾸지 않는 왼쪽, 오른쪽과 맞바꿀 상대가 없는 처음, 마지막 행에서도 Alt와 방향키를 브라우저에 넘기지 않아 페이지를 떠나지 않는다(2026-11-01 결정). 이름 칸 같은 글자 입력 안에서는 막지 않는다.

## 클립보드

웹의 클립보드로 복사는 `navigator.clipboard`로 글자를 쓰고, 클립보드 읽기는 두지 않는다.

- 내용: 지금 화면의 자리 순서대로 자리마다 `[캐릭터 이름, 서버, 모험단명]`을 쓰고 자리 사이를 `, `로 잇는다. 값에 따옴표를 붙이지 않는다. 캐릭터를 찾지 못했지만 인식하거나 입력한 이름이 있는 자리는 `[이름, , ]`, 이름도 없는 빈 자리는 `[]`다. 모험단명이 없으면 그 칸을 비운다.
- 파티와 공대 모두 맞바꾼 뒤의 화면 자리 순서를 따른다. 파티는 네 자리를 한 줄에 쓰고, 공대는 파티(네 자리)마다 줄을 나눠 세 줄을 쓰며 마지막 줄 말고는 줄 끝에 `,`를 붙인다.
- 결과 표시: 복사하면 아이콘이 1.5초 동안 체크 모양으로 바뀌고 보조 기술에 `클립보드로 복사했습니다.`를 알린다. 실패하면 `클립보드에 복사하지 못했습니다.`를 보이고 보조 기술에도 알리며, 다음 복사가 성공하면 걷는다. 연달아 누르면 마지막 복사의 결과만 보인다.

## 플랫폼 연결

웹 앱의 컴포넌트는 전역 대신 `packages/client/src/hooks/useClientHost.ts`의 `ClientHost`(`party`, `raid`, `getTodayGrade`)로 검색, 캡처, 등급 연산을 받는다. 웹 entry가 브라우저 host를 React context로 넣는다. `party`, `raid`는 공용 검색 코어에 `fetch`, `createImageBitmap` adapter를 넣어 구현하고, 클립보드는 위 [클립보드](#클립보드)대로 `navigator.clipboard`를 바로 쓴다.


컴포넌트와 hook은 아래 세 주입 지점만 웹을 위해 고친다. 그 밖의 웹 전용 분기는 브라우저 host와 웹 entry에 둔다.

- **캡처 소스 요청**: 창 목록 선택 대신 화면 공유를 요청하는 길을 host가 넣는다. 웹 entry가 상단 바의 캡처 칩 자리에 게임 연결 칩을 넣고, 칩은 host가 받은 공유를 창 선택으로 회차에 등록한다.
- **붙여넣기로 회차 시작**: 창 선택 다음 회차 시작 순서 밖에서, 붙여 넣은 프레임으로 회차를 시작하는 길을 host가 넣는다. host가 붙여 넣은 이미지를 들고 있다가 그 회차의 프레임 읽기(`readCaptureFrame`)로 돌려주며, 공대는 host가 공용 공대 crop으로 12행을 만들어 넘긴다. 붙여 넣은 회차도 같은 번호로 센다.
- **웹용 상태 문구**: 붙여넣기, 화면 공유 기준의 상태 문구를 웹 entry가 한 벌로 넘긴다. 던파 창을 연결한 직후와 회차를 마친 뒤의 문구는 [마을 자동 인식](#마을-자동-인식)을 안내한다(예: 파티 화면에서 `마을에서 파티 구성이 바뀌면 자동으로 인식합니다.`).

마을 자동 인식은 새 주입 지점을 더하지 않는다. 자동 회차는 붙여넣기로 회차를 시작하는 길을 그대로 써서, host가 판정에 쓴 프레임을 들고 있다가 그 회차의 `readCaptureFrame`으로 돌려준다. 자동 인식 때문에 세 주입 지점 밖의 컴포넌트 코드를 고치지 않는다.

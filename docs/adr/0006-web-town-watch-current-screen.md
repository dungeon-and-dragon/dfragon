# ADR 0006: 마을 자동 인식은 지금 화면만 보고 같은 구성을 차이가 큰 픽셀 수로 정한다

## 상태

채택. [ADR 0005](0005-web-town-auto-recognition.md)의 판정 대상 화면(공대 우선), 자동 화면 전환과 그 구조 문장(웹 entry가 검색 모드 store로 화면을 바꿈), 같은 구성 기준을 대체한다. 마을 판정, 2번 연속, 회차, 진행 중과 실패, 주기는 ADR 0005 그대로다. 구조는 감시는 브라우저 host가 맡고, 판정은 host와 분리한 순수 모듈에 두며, 자동 회차는 붙여넣기 회차의 길(host가 판정에 쓴 프레임을 그 회차의 `readCaptureFrame`으로 돌려줌)을 쓴다는 부분만 남는다. 계약은 [웹 클라이언트](../rules/web-client.md#마을-자동-인식)에 둔다.

## 맥락

ADR 0005의 판정 규칙을 순수 모듈로 구현한 [PR #1112](https://github.com/dungeon-and-dragon/dfragon/pull/1112)의 리뷰에서 두 문제가 드러났다.

- **공대 우선과 자동 화면 전환**: 판정이 공대 창과 파티 프레임을 함께 보고, 구성이 새로운 쪽으로 웹의 화면을 바꾼다. 파티 회차가 아직 없으면 공대 회차만 하고 공대 창을 닫을 때 파티 회차가 시작되고 화면도 파티로 바뀌어, "공대 창을 닫는 것만으로는 파티로 돌아가지 않는다"와 어긋난다. 이를 막으려면 두 화면의 기준과 우선순위를 함께 다루는 규칙이 더 늘어난다.
- **평균 차이 비교**: 구현은 이름 crop의 RGB 평균 절대 차이가 6 이하이면 같은 구성으로 봤다. 글자 하나만 다른 이름은 바뀐 픽셀이 crop 전체에서 희석되어 이 기준을 넘지 못할 수 있다.

## 확인한 사실

- 1067×600 화면의 파티 이름 crop(73×16) 표본에서 같은 이름끼리의 RGB 평균 차이는 0.00, 다른 이름끼리는 25~65였다.
- 글자 하나만 다른 이름(예: `늑머`, `늑머2`)은 실제 쌍으로 재지 않았다. 글자 하나가 73×16 crop에서 수십 픽셀을 바꾼다고 보면 평균 차이는 약 6이고, 표본 crop의 가로 60~80% 열만 다른 이름 crop으로 바꾼 실험에서는 0.4~11.5였다. 평균 허용 오차 6에서는 같은 구성으로 판정될 수 있다.
- 화면 공유 프레임은 같은 화면에서도 색이 채널마다 1~3 흔들린다([Issue #1076](https://github.com/dungeon-and-dragon/dfragon/issues/1076)).

## 선택지

| 선택지 | 고르지 않은 이유 |
| --- | --- |
| A. 공대 우선과 자동 화면 전환을 두고, 파티 회차가 없을 때의 규칙을 더한다 | 두 화면의 기준과 우선순위를 함께 보는 규칙이 더 복잡해진다. |
| B. 웹의 지금 화면에 맞는 창만 보고, 화면은 사용자가 바꾼다 | 채택 |
| C. 평균 차이의 허용 오차를 줄인다 | 글자 하나의 변화는 crop이 클수록 평균에서 더 희석되고, 흔들림(1~3)과의 여유도 거의 남지 않는다. |
| D. 채널 차이가 큰 픽셀의 수로 비교한다 | 채택 |

## 결정

B와 D를 채택한다(2026-11-03 저장소 소유자 결정, "로직을 분리해서 간단하게").

- **지금 화면만**: 웹이 파티 화면이면 게임의 파티 프레임만, 공대 화면이면 공대 상세 창만 본다. 공대 우선과 "공대 창을 닫아도 파티로 돌아가지 않음"은 없어진다.
- **화면 전환 없음**: 자동 인식은 웹의 화면을 바꾸지 않고 지금 화면의 회차만 시작한다. 화면은 사용자가 바꾼다.
- **같은 구성**: 픽셀마다 RGB 채널 절대 차이의 최대값이 임계값을 넘으면 바뀐 픽셀로 세고, 바뀐 픽셀이 일정 개수 이상이면 다른 구성이다. 처음 값은 픽셀 임계값 32, 개수 10이며 둘 다 잠정 값이다. 32는 [Issue #1076](https://github.com/dungeon-and-dragon/dfragon/issues/1076)에서 색 패턴의 원본과 공유 결과가 다르던 1~3을 넘는 값이지만, 글자 가장자리의 YUV 4:2:0 차이가 32 이하라는 근거는 없다. 10은 글자 하나가 수십 픽셀을 바꾼다는 추정에서 정했고, 그중 채널 차이가 32를 넘는 픽셀이 10개 이상인지는 확인하지 않았다. [Issue #1110](https://github.com/dungeon-and-dragon/dfragon/issues/1110)의 dev 사이트 확인에서 실제 공유 crop으로 같은 이름과 한 글자만 다른 이름의, 채널 차이가 32를 넘는 픽셀 수를 재어 맞춘다.
- **이어 세기**: 2번 연속은 같은 화면의 틱만 이어 센다. 사이에 웹의 화면이 바뀌거나 그 화면의 창을 찾지 못한 틱이 끼면 처음부터 다시 센다.

## 결과

- 파티 화면을 보는 동안에는 게임에서 공대 상세 창을 열어도 공대 회차는 자동으로 시작하지 않는다. 파티 프레임이 보이고 구성이 바뀌면 파티 회차는 시작한다. 공대를 자동으로 인식하려면 사용자가 웹을 공대 화면으로 바꿔 둔다.
- 웹 entry가 자동 인식 때문에 검색 모드를 바꾸지 않는다.
- 두 임계값이 맞으면 글자 하나만 바뀐 이름도 다른 구성으로 본다. 확인 전까지는 다음 경우가 남는다.
  - **놓칠 수 있는 경우**: 획 일부만 다른 이름이나 배경과 대비가 낮은 글자는 채널 차이가 32를 넘는 픽셀이 10개에 못 미쳐 같은 구성으로 남을 수 있다.
  - **잘못 시작할 수 있는 경우**: 같은 이름이라도 글자 가장자리 잡음으로 채널 차이가 32를 넘는 픽셀이 10개 이상 생기면 회차가 한 번 더 시작될 수 있다.

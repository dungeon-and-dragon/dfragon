# ADR 0007: 마을 자동 인식의 같은 구성은 OCR과 같은 글자 이진화 결과로 비교한다

## 상태

채택. [ADR 0006](0006-web-town-watch-current-screen.md)의 같은 구성 기준(RGB 채널 차이가 큰 픽셀 수)을 대체한다. 지금 화면만 보는 규칙과 화면 전환 없음, 이어 세기는 ADR 0006 그대로다. 계약은 [웹 클라이언트](../rules/web-client.md#마을-자동-인식)에 둔다.

## 맥락

[Issue #1110](https://github.com/dungeon-and-dragon/dfragon/issues/1110)의 dev 사이트 확인에서, 공대 화면을 보는 동안 공대 구성이 바뀌어도 자동 회차가 시작되지 않았다.

공대 상세 창의 이름 칸 배경은 노랑, 보라, 하늘색처럼 여러 색으로 움직이고, 일부는 반투명해 창 뒤의 마을 화면이 비친다. 이름이 그대로여도 프레임마다 이름 crop의 RGB 픽셀이 달라져, 연속한 두 프레임이 늘 다른 구성으로 판정되고 2번 연속 조건이 맞지 않았다.

## 확인한 사실

2026-11-03 Windows 실기에서 공유 중인 던파 창을 1초 간격으로 찍어 공대 이름 crop을 비교했다([Issue #1117](https://github.com/dungeon-and-dragon/dfragon/issues/1117)).

- 이름이 그대로인데도 연속한 두 장 사이에 채널 차이가 32를 넘는 픽셀이 행마다 145~273개였다. ADR 0006의 기준은 10개 미만이면 같은 구성이다.
- OCR의 공대 닉네임 전처리(가장 어두운 채널의 crop별 Otsu 이진화, 선택 행 테두리 제거, 떨어진 픽셀 제거)를 거친 뒤 글자 여부가 다른 픽셀을 세면, 같은 이름의 연속 프레임은 모두 0개였다(노란 배경 12행 5쌍, 보라 배경 1행 5쌍). 같은 노란 배경 프레임을 RGB로 비교하면 행마다 176~254개가 달랐다.
- 같은 방법으로 1067×600, 3840×2160 표본의 서로 다른 공대 이름 526쌍은 최소 79개가 달랐다. 이 쌍은 이름 전체가 다르며, 이름은 가운데 정렬이라 글자 수가 바뀌면 글자 전체가 밀려 차이가 커진다.
- 같은 폭의 한 음절만 바뀐 이름 쌍은 재지 않았다. 표본 crop 하나의 글자 픽셀은 71~209개(4~6음절)라 음절당 약 20~40개로 추정하며, 획 일부를 공유하면 차이는 더 작다.
- 파티는 OCR 파티 경로의 BT.601 회색 Otsu 이진화로 비교하면 표본의 같은 이름끼리 0개였다. 서로 다른 파티 이름의 최소값은 재지 않았다.

## 선택지

| 선택지 | 고르지 않은 이유 |
| --- | --- |
| A. RGB 비교의 채널 차이나 픽셀 개수 임계값을 올린다 | 같은 이름의 차이가 배경이 얼마나 움직이는지에 따라 정해져, 다른 이름과의 간격을 보장하지 못한다. |
| B. 이름 칸 배경 색을 고정 임계값으로 찾아 지운 뒤 비교한다 | 배경과 글자 색이 노랑, 보라, 하늘색 등으로 바뀌어, 색이 바뀌면 깨진다(저장소 소유자 지적). |
| C. 틱마다 OCR로 이름을 읽어 비교한다 | [ADR 0005](0005-web-town-auto-recognition.md)에서 고르지 않은 대안이다. 공대 이름 12장만 읽어도 판정 주기(약 1초)를 넘는다. |
| D. OCR과 같은 글자 이진화 결과에서 글자 여부가 다른 픽셀 수로 비교한다 | 채택 |

## 결정

D를 채택한다.

- **이진화**: 그 화면의 OCR 닉네임 전처리를 그대로 쓴다. 파티는 BT.601 회색의 Otsu 이진화, 공대는 가장 어두운 채널의 Otsu 이진화 뒤 선택 행 테두리와 떨어진 픽셀을 지운다. 임계값은 crop마다 Otsu로 정하므로 특정 색에 기대지 않는다.
- **같은 코드**: 공대 전처리 순서는 OCR 경로와 자동 인식이 한 함수를 함께 써서 갈라지지 않게 한다.
- **같은 구성**: 자리 수와 자리별 crop 크기가 같고, 자리마다 글자 여부가 다른 픽셀이 10개 미만이면 같은 구성이다. 10은 끝 숫자 `1`→`2`나 한 음절 교체처럼 같은 폭의 글자 하나만 바뀐 이름을 잡도록 음절당 추정 글자 픽셀(약 20~40개)보다 낮게 둔 값이다. 같은 이름은 실측 0개라 여유가 있다. 실제 화면 공유(YUV 변환)에서 같은 이름의 글자 가장자리 픽셀이 몇 개 바뀌는지는 [Issue #1110](https://github.com/dungeon-and-dragon/dfragon/issues/1110)에서 확인한다.
- ADR 0006의 RGB 비교(채널 차이 32를 넘는 픽셀 수)는 지운다.

## 결과

- 이름 칸 배경의 색이 바뀌거나 움직여도 같은 이름은 같은 구성으로 남고, 한 자리라도 이름이 바뀌면 2번 연속 판정 뒤 그 화면의 회차가 시작된다.
- OCR 닉네임 전처리를 바꾸면 자동 인식의 같은 구성 판정도 함께 바뀐다. 전처리를 바꿀 때는 두 동작을 함께 확인한다.
- 다음 경우는 남는다.
  - **놓칠 수 있는 경우**: 획 일부만 다른 이름은 글자 여부가 다른 픽셀이 10개에 못 미쳐 같은 구성으로 남을 수 있다. 한 음절만 바뀐 이름 쌍과 서로 다른 파티 이름의 최소값은 재지 않았다.
  - **잘못 시작할 수 있는 경우**: 화면 공유의 색 변환이나 배경 변화로 Otsu 임계값이 옮겨 글자 가장자리가 10개 이상 바뀌면 같은 이름으로 회차가 한 번 더 시작될 수 있다. 실기 표본에서는 0개였다.

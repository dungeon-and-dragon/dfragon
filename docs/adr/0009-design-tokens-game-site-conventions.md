# ADR 0009: 디자인 토큰을 게임 전적 사이트의 관습에 맞춰 바꾼다

## 상태

채택. 공용 토큰의 무채색 바탕, 글자, 테두리, 신호색, danger 계열과 상단 바 높이를 이 결정의 값으로 바꾼다. 컴포넌트 형태, 헤더 구조, 글꼴은 아래 [정하지 않은 것](#정하지-않은-것)에 두고 후속 PR에서 정한다.

## 맥락

던삐삐 디자인은 dfragon-design 저장소의 `tokens.json`과 캔버스 시안에서 나왔고, 크림색 신호색 `#F8E8C8`과 오른쪽 위를 자른 주 버튼이 특징이었다. 2026-11-04 저장소 소유자가 현재 디자인 맥락을 두지 않고 게임 사이트가 공통으로 쓰는 디자인 체계를 가져오기로 했다.

OP.GG, DAK.GG, DOR.GG, Overwolf, CurseForge의 첫 화면, 목록, 상세 화면 14개를 1440×900 다크 선호로 열어 렌더된 computed style을 읽었다. 소스 코드, 아이콘, 문구는 가져오지 않고 값과 구조만 봤다. 다섯 곳에서 겹친 것은 다음과 같다.

- 다크 바탕에 배경 3~4단계(캔버스, 바, 표면, 컨트롤)와 글자 3단계(기본, 보조, 흐림). 면은 색과 1px 테두리로 나누고 그림자는 팝오버에만 쓴다.
- 채도 높은 강조색 하나를 버튼, 탭 밑줄, 활성 칩, 포커스에만 쓰고 승/패, 티어, 경고색은 따로 둔다.
- 4px 간격 체계와 0~4px 모서리. pill은 칩과 아바타에만 쓴다.
- 전적 사이트(OP.GG, DAK.GG)는 본문 14px, 보조 12px, 바닥 11px, 버튼 40px, 작은 버튼 32~36px, 전역 바 + 게임 바 2단 헤더, 첫 화면의 50~60px 검색창, 콘텐츠 폭 1080px이다.

갈린 것은 강조색 색상(파랑, 주황, 빨강, 보라), 글꼴(한국 사이트 둘은 Pretendard), 모서리 0/2/4px, 헤더 높이 48~64px, 게임 바의 브랜드색 여부, 콘텐츠 폭, 라이트 지원, 등급 표현(행 바탕 또는 숫자 색)이다. 이 항목은 후보를 나란히 그린 초안 페이지에서 소유자가 골랐다. DOR.GG는 전적 사이트가 아니라 클립 커뮤니티라 데이터 화면 관습의 근거에서 뺐다.

## 결정

겹친 항목은 그대로 쓰고 갈린 항목은 다음으로 정한다.

| 항목 | 결정 | 값 |
| --- | --- | --- |
| 무채색 바탕 | 약간 차가운 회색 6단계 | canvas `#131417`, bar `#18191D`, surface `#1E1F24`, inset `#25262C`, control `#2C2D34`, control hover `#34353D` |
| 테두리 | 배경보다 한 단계 밝은 1px | default `#2A2B32`, strong `#3B3D46` |
| 글자 | 4단계 | default `#F2F2F4`, muted `#A3A6B1`, subtle `#70737E`, disabled `#4B4D56` |
| 신호색 | 오렌지. 전적 사이트 관습(DAK.GG, CurseForge의 주황 계열)과 로고 빨강 `#E83830`과 같은 난색 | signal `#FF7A33`, hover `#FF9357`, on-signal `#1A0E07` |
| danger | 신호색 난색과 구분되는 빨강 | `#FF5C5C`와 그 16% 면 |
| 모서리 | 패널 0, 컨트롤 2px. 현재 값 유지 | |
| 상단 바 | 전역 바 48px + 게임 바 40px 2단 무채색 | size-topbar `48px`. 화면 적용은 아래 정하지 않은 것 |
| 콘텐츠 폭 | 1080px 고정. 화면 적용은 아래 정하지 않은 것 | |
| 등급, 실패 표현 | 표 행은 숫자와 배지 색만 바꾸고 행 바탕은 물들이지 않는다 | 티어, 검색 실패 색 유지 |
| 라이트 모드 | 이번 결정은 다크 값만 정한다. 라이트 값은 규칙 문서의 provisional 상태 그대로다 | |

의미색과 역할색(success, warning, 티어, 점수 역할, 검색 실패, 모험단, 희귀도, 강화, 속성, 묵언의 진, 공대 파티)은 값을 유지한다. 브랜드 크림 `#F8E8C8`은 로고 자산 색 `brandCream`으로 남기고 신호색에서는 뺀다. 토큰 이름은 바꾸지 않고 값만 바꿔 사용처를 손대지 않는다. 주 버튼은 hover에서 `signalHover`를 쓴다.

후보 가운데 민트 `#3EDBB8`은 랭커 티어색 `#50E3C2`와, 바이올렛 `#9B8CFF`는 레어 등급색 `#B36BFF`, 묵언의 진 사거리 색 `#A066FF`와 겹쳐 택하지 않았다. 파랑은 OP.GG와 같아 보이고 딜러 점수색과 겹치며, 빨강은 danger와 겹쳐 후보에서 뺐다.

## 정하지 않은 것

- 헤더 2단 구조는 화면 배치 변경이라 이 결정에서 높이만 정하고 구현은 후속 PR에서 한다. 상단 바 높이 토큰 `--df-size-topbar`는 48px로 바꾸지만 소비처가 없고, 현재 상단 바는 `TopBar`의 44px 직접 값이며 앱 창 높이 163px, 300px에 묶여 있어 화면은 그대로다.
- 콘텐츠 폭 1080px도 현재 앱이 1280px 고정 창이고 공대 12인 배치와 캡처 비교가 창 크기에 묶여 있어 헤더 2단과 같은 후속 PR에서 정한다.
- 카드 상태 면은 유지한다. 랭커 카드의 물든 배경 `tierRankerSurface`, `tierRankerWell`과 검색 실패의 옅은 면 `cardFailureWeak`은 초안이 다룬 표 행이 아니라 카드 상태 표현이라 값만 새 팔레트에 맞췄다. 없앨지는 후속 PR에서 정한다.
- 자른 모서리(`shapes.cutTopRight`, `--df-cut`)는 초안 화면에 없지만 주 버튼, 칩, 실패 표시, 공대 파티 번호, 목록 열림 모양에 얽혀 있어 유지 여부를 후속 PR에서 정한다. 그때까지 규칙 문서의 형태 항목은 그대로다.
- 글꼴은 초안에서 Pretendard를 골랐으나 현재 웹 앱은 2026-10-26 결정의 마루미냐 한글을 쓴다. 초안 페이지는 "현재 토큰도 Pretendard"라고 안내했는데 이는 `packages/ui`의 기본값이고 실제 웹 앱은 `apps/web`의 전역 CSS가 마루미냐 한글로 덮어쓴다. 안내가 틀린 상태에서 고른 것이라 바꿀지는 소유자가 다시 정한다. 숫자 글꼴도 초안은 같은 글꼴과 tabular-nums를 골랐으나 Barlow Condensed를 유지하며 같이 정한다.
- dfragon-design `tokens.json` 반영은 그 저장소의 PR로 한다. 반영 전까지 `tokens.css` 머리말이 이 ADR을 기준으로 가리킨다.

## 결과

- `packages/ui/tokens.css`의 무채색, 글자, 테두리, 신호색, danger 계열, card 토큰(`--df-card-*`), 꺾쇠 기본색이 바뀌고 `--df-signal-hover`가 생긴다. 상단 바 높이 토큰은 48px로 바뀌지만 소비처가 없어 화면의 상단 바는 그대로다.
- 웹 앱 상자(`apps/web`)의 배경이 하드코딩한 옛 캔버스 색 대신 `bgCanvas` 토큰을 읽는다.
- 규칙 문서의 색, 크기 값이 이 ADR을 따른다. 화면마다 보이는 차이는 신호색이 크림에서 오렌지로, 바탕이 따뜻한 회색에서 차가운 회색으로 바뀌는 것이다.

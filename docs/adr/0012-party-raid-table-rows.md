# ADR 0012: 파티, 공대 화면을 카드 격자 대신 표의 행으로 그린다

## 상태

채택. 2026-10-31 이후의 파티 4칸, 공대 4열 3줄 카드 격자와 그 카드 상태 표현(네 모서리 꺾쇠, 빨간 빗금, 카드 상태 면)을 대신한다. [ADR 0010](0010-two-tier-header-1080-width-no-cut-corners.md)의 1080px 상자와 2단 상단 바는 그대로 쓴다.

## 맥락

웹 앱은 한 줄, 세 줄로 정해진 게임 HUD 비율을 따라 카드를 늘어놓을 이유가 없다. 카드 격자는 자리마다 이름, 소속, 명성, 점수를 세 줄로 접어 담아 공대 12자리가 1080px 안에서 좁았고, 같은 값을 자리끼리 세로로 비교하기 어려웠다.

카드 상태는 꺾쇠 색, 카드 면, 빗금 같은 장식으로 구분했다. 실패와 오류의 원인은 짧은 안내 뒤에 "다음 조회 방법"을 덧붙인 문장이었고, API가 오류 응답에 담아 보내는 `error.message`는 클라이언트가 버리고 자체 문구로 바꿨다.

소유자는 캔버스에서 표(A), 공대 세로 3열(B), 52px 행 카드(C) 세 배치를 보고 표를 골랐다. 이어 표의 행 상태 21가지를 한 보드에 그려 정했다.

## 결정

- 파티와 공대 화면은 같은 표 하나로 그린다. 헤더 32px, 행 48px, 초상화 36px이다. 열은 자리(64), 캐릭터, 서버(96), 모험단(150), 길드(110), 직업(140), 명성(100), 점수(120), 스냅샷(96)이고 캐릭터 열이 나머지 폭을 쓴다. 열 폭은 내용과 관계없이 고정하고 넘치는 글자는 말줄임한다.
- 공대는 R, Y, G 파티마다 28px 파티 헤더 행에 파티 배지와 "찾은 수/4"를 둔다. 자리 배지는 그 파티 색의 옅은 면(16%)에 색 글자다. 파티는 자리 번호만 둔다.
- 점수 열은 딜러 "장비" 라벨과 파란 숫자, 버퍼 "버프" 라벨과 초록 숫자다. 상위, 랭커는 명성 숫자 색과 이름 옆 외곽선 배지만 바꾸고 행 바탕과 점수 색은 바꾸지 않는다.
- 실패와 오류는 모험단 자리부터 세 칸을 합친 한 줄 글자다. 검색 결과 없음과 OCR이 이름을 읽지 못한 경우, 이름 없는 Enter는 노란 글자, 검색 오류는 빨간 글자다. 상세 정보 오류는 모험단, 길드, 직업을 두고 명성과 점수 두 칸에 빨간 글자를 둔다. 문구 뒤에 다음 조회 방법을 덧붙이지 않는다.
- 검색 오류와 상세 정보 오류의 문구는 API 오류 응답의 `error.message`를 그대로 쓴다. 응답을 받지 못한 실패(통신 실패, timeout, 응답 검증 실패)와 클라이언트가 보내기 전에 거절한 입력만 클라이언트 문구를 쓴다.
- 회차 진행은 세 점과 단계 이름이다. 이름 인식, 캐릭터 검색은 모험단 자리에, 상세 정보 확인은 명성과 점수 자리에 둔다.
- 스냅샷 열에는 순번 배지(핀 아이콘과 순번) 하나만 둔다. 스냅샷 때와 같은 자리의 모험단은 신호색 외곽선, 자리가 바뀐 모험단은 신호색으로 채운 배지, 스냅샷에 없는 모험단은 빨간 핀 배지 "없음"이다. 공대의 순번은 `파티-순번`(예: `2-1`)이다. 실패한 행에는 배지를 두지 않는다.
- 자리 맞바꾸기의 방향키는 표의 행 방향을 따라 Alt와 위, 아래 방향키다. 공대는 파티 경계를 넘어 위아래 행과 맞바꾼다. 드래그와 맞바꾼 뒤 포커스 복귀는 그대로다.
- 카드 프레임(`CardFrame`), 네 모서리 꺾쇠(`CornerBrackets`), 빗금, 격자, 주사선 shape과 그것만 쓰던 토큰(`bracket*`, `hatchAlert`, `gridLine`, `bgWell`, `cardBg`, `cardBgWaiting`, `cardFailureWeak`, `cardFgAdventure`, `tierRanker{Surface,Well,Outline}`, `shape.*`)을 지운다. 공대 파티 색은 게임 배지의 진한 면 대신 글자 색과 옅은 면 한 쌍으로 바꾼다.

## 정하지 않은 것

- 같은 이름 후보가 여럿인 행의 "후보 N" 칩과 후보 창, 서버 선택 팝오버는 #1159에서 정한다. 그 전까지 파티의 후보가 여럿인 행도 자동으로 고른 후보(얼굴 거리가 가장 작은 후보, 거리가 없으면 최고 명성)를 보통 행으로 보이며, 다른 후보는 서버 버튼으로 직접 고른다. 후보 목록과 미리보기, 확정의 선택 상태는 #1159의 새 창이 다시 쓰도록 남긴다.
- 이름 칸 Enter와 서버 선택으로 한 직접 조회는 후보 검색과 상세를 한 요청으로 받으므로, 상세를 받지 못하면 검색 실패로 끝나 모험단 자리에 빨간 문구가 보인다. 캐릭터를 남기고 명성과 점수 자리에 오류를 두는 모양은 캡처 회차의 상세 실패에만 적용되며, 직접 조회의 실패 흐름을 나누는 일은 이 결정에서 하지 않았다.
- 라이트 모드의 표 색은 정하지 않았다. 웹 앱은 다크 하나다.
- dfragon-design `tokens.json`에서 지운 토큰과 공대 파티 색을 고치는 일은 그 저장소의 PR로 한다.

## 결과

- 상자 높이가 내용에 맞춰 파티는 헤더와 네 행, 공대는 헤더와 파티 헤더 행 세 개, 열두 행이 된다.
- 붙여넣기와 화면 공유로 인식한 결과, 후보 검색, 상세 조회의 동작은 바뀌지 않는다. 슬롯에 담기는 검색 오류에 API `message`가 더해지고, 상세 정보 실패에는 그 오류가 따로 담긴다.
- 파티 화면의 후보 창이 #1159 전까지 보이지 않는다.
- Alt와 왼쪽, 오른쪽 방향키는 더 이상 자리를 맞바꾸지 않는다. 앱 상자 안에서 브라우저의 뒤로, 앞으로 가기를 막는 동작은 그대로다.
- 규칙 문서의 화면 구성, 카드 상태 항목, `packages/ui/tokens.css` 머리말과 `packages/ui` README가 이 결정을 따른다.
